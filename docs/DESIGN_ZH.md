# Estuary v1 策略概览

本文概述冻结源码的已有行为，不代表新增优化。游戏数值和机制对应原发布环境；后续补丁需要单独核验。

| 模块 | 作用 |
| --- | --- |
| `main.cpp` | 选人与英雄回合入口、异常日志、交还回合 |
| `state.hpp` | 静态地图、营地记忆、共享认领、当前威胁快照 |
| `navigation.hpp` | 地形和距离场、接近目标、跨区与撤离 |
| `combat.hpp` | 普攻、技能类型、控制、护盾和治疗 |
| `economy.hpp` | 碎片购买、献祭、祭坛锁、回城和恢复 |
| `planner.hpp` | 选人、营地收益与风险、任务选择和调度 |

## 资源循环与任务

主要目标是获取宝石并安全献祭，同时将金币投入清怪能力和生存能力。英雄回合按即时 SDK 状态处理购物、引导、死亡、恢复、治疗、紧急撤离、宝石兑现、近处战斗机会和清营任务。

队伍通过 8 字节共享内存中的槽位记录营地认领，减少重复跑向同一小营地。死亡、恢复或任务结束时释放认领；没有安全独占任务时允许有限的协助清理。该实现不是完整的共同任务协议、计划轮换承伤或接力运输系统。

营地选择结合收益、路线、预计清理时间、承伤和风险。整组出生格均在当前视野内时使用可见成员状态，否则保持静态估计及自身历史记录。不能把未看见的状态当成已确认的活怪或攻击对象。

## 导航、战斗与经济

移动使用合法地图与当前单位阻挡，目标设为能够攻击、占领或献祭的位置；跨区域时考虑冲刺和传送水晶。移动后可能改变视野与行动额度，后续调用按即时状态检查。规划缓存和有限次尝试用于控制每回合成本。

战斗按技能元数据处理伤害、控制、治疗、护盾、重置与冲刺。近处可击杀敌人、携宝敌人和献祭者可成为战术目标。低血或高风险时撤离并恢复。

经济逻辑包括徽章与属性购买、回城消费、跨区工具和祭坛锁。交分任务受阻时有暂避与恢复流程，减少持续执行同一失败导航的情况。

## 已知局限

- 营地清理时间与承伤采用启发式估计；范围伤害可能唤醒相邻营地，单组估算不能充分描述这种集中承伤。
- 威胁快照可能尚未反映本回合刚打醒或刚击杀的怪，误差可能向两个方向发生。
- 协作和祭坛控制能力有限，没有完整阵容搜索、技能连招搜索或敌方未来路线预测。
- 固定的选人、经济权重和阈值不被声称为最优参数；历史测试也不能证明所有地图与后续运行环境都无错误。

源码的精确字节及原发布构建产物以仓库哈希清单为准。此次归档没有重新测试对局表现。
